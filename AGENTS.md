# AGENTS.md

- Commit straight to `main` and push: no branches, PRs or MRs.
- During testing, pls never trigger Keychain or admin-password prompts.
- Test only on the Personal account, in Jira project QA (QA Scratch). CON tracks Conductor's real work (open and close this repo's issues there) and ST (Sample Tasks) holds showcase data: don't test there. The Work account stays read-only.
- Never modify anything in corporate work Jira accounts: no edits, comments, transitions or assignments, from the API or the app. Reading is fine. Keys sent to the app land in whatever it shows, and a relaunch can restore a work list: drive only windows of QA issues opened by link (`open -g conductor://issue/QA-14`, then `drive.swift raise QA-14`).
- Build with `xcodebuild -scheme Conductor -allowProvisioningUpdates build`, without `-derivedDataPath`: Xcode's per-user workspace setting (git-ignored; on a new clone: File → Project Settings → Advanced → Custom, relative to workspace, `build/Build/Products` and `build/Build/Intermediates.noindex`) sends every local build (Xcode, command line, tests) to `build/`, and the flag's other cache paths make Xcode and the command line recompile everything each time you switch. Release (Product → Archive) is the App Store build; the GitHub build is Release plus `SWIFT_ACTIVE_COMPILATION_CONDITIONS=GITHUB_BUILD` (`.github/workflows/release.yml`), which adds the update check and the license line on the sign-in card. Debug has the flag too.
- After a build, quit every running Conductor (`pkill -x Conductor`; one Xcode launched ignores signals while debugged, so `osascript -e 'tell application "Xcode" to stop workspace document 1'`) and start the new one with `open -n build/Build/Products/Debug/Conductor.app`, so the user is never left with a stale build. Find windows with their CGWindow ids and `screencapture -l` instead of clicking around.
- When the user reports a bug that no existing check covers, add a check for it to the "Regression watchlist" in `qa/QA-SPEC-FULL.md` (the full QA run; all testing files and reports live in the git-ignored `qa/` folder), so every later full run tests it.
- For a scroll-rate check, launch a Debug build with `CONDUCTOR_FRAMES=1` (`--stderr <log>`): it prints the main thread's late display-link ticks once a second. `qa/drive.swift` raises a window, scrolls it with trackpad-style events, clicks and types while the app stays in front; `qa/QA-SPEC-PERF.md` P10 has the method and numbers.
- For frame-level UI checks (a layout shift, a flash), record the window with `qa/record-window.swift` (ScreenCaptureKit, streams only Conductor's windows), not screenshots. A locked screen locks the data protection keychain, so the main window waits on a spinner: test from `.env` accounts only through a local, uncommitted bypass that never saves to the keychain.
- Test Jira Server / Data Center on the local Docker instance: containers `jira-dc` (Jira Software DC, port 8080) and `jira-db` (Postgres 17), account 3 in `.env` (a personal access token in `KEY_3`). Its license is Atlassian's 3-hour timebomb key for Jira Software Data Center (developer.atlassian.com, "Timebomb licenses for testing server apps"). It counts the three hours from Jira's start, so `docker restart jira-dc` (about two minutes) gives three more; an expired instance turns read-only. `LiveServerTests` runs every Server read and write against it (`TEST_RUNNER_CONDUCTOR_SERVER_SITE/_TOKEN/_PROJECT`).
